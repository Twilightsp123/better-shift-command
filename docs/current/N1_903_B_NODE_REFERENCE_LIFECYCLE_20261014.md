# BSC N1 — B 路线节点 node+0x70 的真实来源、参考失效与重建分支（2026-10-14）

## 审计范围与版本

用户提供的原始 `Warhammer3.exe` 已在本轮重新进行 SHA256 校验：
`518c4f292f275142df13b96b9db704a3db7b4870b2c519df83d850596ecc822a`。
PE ImageBase 为 `0x140000000`，本文全部函数地址均为 **RVA**。

只读独立原始 EXE 审计通过：**140/140 opcode 与 GNU objdump 真正指令起点、17/17 E8 目标、8/8 JCC 目标、3/3 类型化虚表槽**。实际本地运行 **17/17 回归测试 PASS**，其中一项使用这份原始 EXE，其余包含修改寄存器、增加叶函数调用等负例。上述全部属于 `EXACT_ORIGINAL_EXE_STATIC` 和 `SYNTHETIC_CONTRACT`，不是游戏内动态调用命中、更不是修复生效。

## 1. 成员可消费的路线节点类型必须明确区分

三张相邻表都被原生构造器独立安装，而非同一张大虚表的跨界偏移：

| 原生虚表起点 | `+0x10` 方法 | 本轮含义 |
|---|---|---|
| `0x03AE00E8` | `0x03281520` | 另一种任务的动作分发，可能间接访问路线节点 `+0x70` |
| `0x03AE0108` | `0x03281600` | 第二种任务动作类 |
| **`0x03AE0128`** | **`0x03281408`** | **当前所追 B 路线节点持有者** |

当前 B 类型真实由 `0x03263AB0` 构造，并在 `0x03263ACF/0x03263AD6` 安装 `0x03AE0128`。不能把 `0x03281520` 的成员分发默认接到本类型。管理器同样有多条表面结构相似的链：B 路线节点是 `manager+0x2D0`，而 `0x03109DD4` 清退的是 **`manager+0x2F8`** 链的另一类节点，后者读取 `+0x70` 不能算成前者的 motor consumer。

## 2. 当前 B 节点普通重算的 RDX 来源终于闭合

原始 `0x03128E80` 先遍历 `manager+0x1F0` 大任务链，然后才遍历 `manager+0x2D0` 的路线节点。对于已识别的 `node+0x04!=0` 和 `node+0x08==0` 的有条件路径：

```text
0x0312907E LEA RDX,[node+0x20]
0x03129082 MOV RCX,RDX
0x03129085 CALL 0x0311BE18          ; 内嵌几何参考验证
0x0312908A TEST EAX,EAX
0x0312908C JE 0x031290A2           ; 验证不通过，跳过
0x0312908E LEA RCX,[manager+0x18]
0x03129092 CALL 0x030FDA9C          ; RDX 仍为 node+0x20
0x03129097 MOV [node+0x70],RAX
0x0312909E MOV [node+0x08],1
```

先前材料因 Windows x64 约定 RDX 为 volatile，没有证明上面两个调用之间的 RDX 连续性。本轮逐条检查 `0x0311BE18` **完整 PE unwind 函数**和真实无 unwind、带两个 `ret` 的叶函数 `0x03037A48..0x03037A68`，确认两者在固定机器码中没有 RDX/EDX/DX/DL 访问；被调用叶函数也没有进一步 `call`。`0x03129085` 返回到 `0x03129092` 的非跳过分支只有 `test eax`、条件跳转、`lea rcx`，也不改写 RDX。最后 `0x030FDAC7 MOV RCX,[RDX]` 确认转换器确实消费该指针。

**因此在这条已证分支内，`RDX = &node+0x20` 的参数来源已经闭合。** 它不是 `bigTask+0x160` 的地址，不应因几何相似而强制类型归并。

## 3. 带旧大任务的路线节点与普通节点不应混同

- **带大任务路径**：`0x03121ABC → 0x030ECB10` 用传入的大任务 `+0x158` 等参数构造 `node+0x70` 路线对象，并在 `0x030ECB2E` 将 `node+0x08=1`。所以正常管理器 Tick 的 `+0x08==0` 重算门槛在刚创建时**不通过**。
- **普通节点路径**：`0x031219B0` 在 `0x03121A25` 清 `node+0x08`，先清 `node+0x70`，并在另一组条件通过时调用 `0x030FDA9C` 转换；通过后才标记 `node+0x08=1`。未完成的普通节点可以在后续 Tick 由上述已证明的 `&node+0x20` 路径生成。

因此，两种节点初始状态、输入来源和重新计算时机不同；**不能默认成功继承的 MOVE 在创建节点后立即把旧方向路线覆盖成普通路线**。

## 4. route+0x78 的写入者与 B 失效消费者已连接

在带任务节点构造器 `0x030ECB10` 中：

1. `0x030ECB98 CALL 0x030FE1E4`，其返回值写到 `node+0x70`。
2. `0x030FE1E4` 内 `0x030FE272 CALL 0x030C1FDC` 创建路线输出对象，返回对象被保存至 RDI。遍历旧子任务链时，`0x030FE284` 将同一对象 RDI 作为 RCX，`0x030FE287 CALL 0x030C7858` 逐段挂接。最后 `0x030FE29A MOV RAX,RDI` 返回该路线对象。
3. `0x030C7858` 在其路线参考验证通过（`0x030C78C5` 虚表调用、`0x030C78C8 CMP AL,1`）的分支中，于 **`0x030C78D0 MOV [route+0x78],RAX`** 写入参考关系。这个写入是**条件性的**，不是任何路线都必然得到非空参考。
4. 第三类型 B 任务在 `0x03281444` 读取 `aux+0x58=node`，在节点有效且未检查过、又保留 `aux+0x20` 大任务引用的条件下，沿 **`node+0x70 → 0x030DEA20`** 比较路线参考；`0x030DEA5F` 对照返回结果和 `route+0x78`。

`0x030DEA55` 使用的 `[vtable+0x160]` 是**虚方法指针偏移**，不是大任务 `task+0x160`，再次不能跨对象归因。

### 路线参考不一致时的原生分支

`0x030DEA20` 返回非零表示所检查的来源引用有不一致时，`0x03281444` 会按真实指令：

- 递减当前路线节点引用计数，令 `aux+0x58=NULL`；
- 递减所关联大任务引用计数，令 `aux+0x20=NULL`；
- 随后由于两者已空，在同一更新函数的创建分支中选择**普通节点构造器** `0x031219B0`，而不是仍用大任务构造器 `0x03121ABC`。

相反，检查未发现失效时，该辅助对象会记下 `aux+0x60=1`，避免在对应条件下重复检查；没有旧子任务时也存在跳过创建的条件。离线反例测试覆盖了“参考匹配保留节点、参考失效转普通节点、旧子任务尚未建立时等待、已有节点无需重建”等四组路径。

**这是一条真实存在的任务引用/路线几何来源切换**，但它也可能是 CA 正常处理过期参考的合法行为。不能未经动态任务代际对应就禁用失效或强行保留旧指针，否则可能造成悬垂引用和真正崩溃。

## 5. 对可修复性与下一步的约束

当前静态最强结果是：`bigTask+0x158 → B 节点原始路线 → route+0x78 参考条件 → 失效后退回普通路线`，加上普通节点 `&node+0x20 → 0x030FDA9C → node+0x70` 的完整参数证明。

还**没有**证明本路线几何经哪个具体成员对象和 motor goal 写入器变成兵模运动，也没有证明用户 Shift 连续折返的某个 MOVE 实例命中了失效分支。A 族本来就有自己独立的按索引 `member[i] / record[i]` 发包，不能在同一次群组分发中默认与 B 并行。

后续优先追 `0x030DEA20` 中的原生参考提供者虚函数实际接收对象及输出的路线对象类型、管理器 B 节点的失效/重新创建序列；只有证明错误的同一 MOVE 实例导致相邻成员目标冲突，才定位最小 Native Patch。不得删除 CA 旧方向投影、取消原生渐进转弯、篡改所有成员朝向或用 Lua 代替 Shift。

**本轮无 gameplay patch，无游戏实测，未改游戏 EXE、主分支或公开上传运行时指针 JSONL。**
