# BSC R39 / 当前对话第5轮：新版 EXE 成员运动写入与对象类型边界（2026-10-18）

**只读静态逆向，不是 gameplay patch；没有新版游戏动态命中证据。**

## 原始 EXE 与验证

新版用户 EXE 为 Windows x64，232531920 bytes，ImageBase `0x140000000`，完整 SHA256：

`9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`

地址全部 RVA。固定 SHA、PE unwind、GNU objdump 真实指令起点：**116/116** 条机器码，**13 个有 unwind 函数和 1 个无 unwind 叶函数**；**9/9** E8，**10/10** 类型化虚表槽，**2/2** 叶函数跳转目标。本地真实新版 EXE 下 **13/13 unittest PASS**，无 EXE 时 **12 PASS / 1 SKIP**。这些验证不代表游戏运行中修好了 Shift。

## 1. 从 ordinary member Tick 到邻近响应

```text
ordinary member vtable 03912950+0x18 -> 03086F04
  03087349 E8 -> 03059BC8 steering
    03059DF7 -> 030679CC neighbor candidate
    0305A06D -> 03121F54 world goal resolve
    0305A800 -> 03085114 pair response
      0308529D-030852A7 -> context+0x1D8 virtual+0x10 (untyped)
  03087351 E8 -> 0308D830 post-steering
```

steering `03059BC8` 完整反汇编 711 条指令；当前已类型化 RDI 成员 `+0x88/+0x90/+0xE0/+0xE8` 的直接存储未在本体出现。这**不排除间接虚调用对最终位置／速度的影响**，不能说它没有物理运动作用。

后续 `0308D830` 的 `0308D8F3` 虽写 `[rcx+0x90]`，但 RCX 来自 `[member+0x58]→+0x440` 上下文，是随机数／状态对象而不是成员世界坐标。另一 `03098670` 函数所写 `+0x88/+0x8C/+0x90` 属于另一个空间边界对象（安装虚表 `03AD4D28`）；均不应误判成士兵位置输出。

## 2. 真正同一成员位置＋派生运动向量写入者

`031612E8` 和 `031614C0` 均具有成员 RDI 对象身份，写入成员 `+0x88/+0x90` 世界坐标，同时以新旧位置差和比例系数派生向量写 `+0xE0/+0xE8`。

| 函数 | 向量写点 | 位置写点 |
|---|---|---|
| 031612E8 | 03161382 / 0316138A | 031613C4 / 031613CF |
| 031614C0 | 03161545 / 0316154D | 03161557 / 03161562 |

限定 `.udata` 可执行节、先经 objdump 指令起点确认的**全部直接 E8 调用者**：
- `031612E8`: `02F89770, 03058E78, 0305904F, 03065961, 0306A8B5, 0306F7BB, 031006AD`（7处）。
- `031614C0`: `03058F1A`（1处）。
- `03058D2C`：无直接 E8；其对象虚表槽真实存在，不能由此声称永不执行。

普通成员 vtable `03912950`：`+0x18=03086F04`、`+0xF0=03164710`、`+0x368=03070A48`、`+0x550=0306F594`。独立的特殊派生成员 vtable `03AD3360`：`+0x18=03086224`、`+0x20=03058D2C`、`+0x368=03070A24`、`+0x550=0306F594`。构造器 `03052BA8` 和 `03051E5C` 分别有实际安装表指令。派生 Tick `03086224` 经 `0308626A` 直接调用普通 Tick `03086F04`。特殊方法 `03058D2C` 遍历 `+0xDC4/+0xDC8` 关联成员数组，在条件下调用 `031612E8` 与 `031614C0`。

这**排除了直接将上述写入器当作全体普通士兵每帧通用 steering 积分器的无证据假设**，但不排除它们的其它状态调用者（例如 `0306F594→0306F7BB`）。

## 3. 新增：特殊成员 virtual+0x368 是条件转发叶函数

特殊成员的 `03AD3360+0x368=03070A24`，而普通成员 `03912950+0x368=03070A48`：

```text
03070A24   RAX = 当前特殊成员
03070A27   RCX = [member+0xD08]
03070A31   如果 NULL → 03070A3D
03070A36   如果非NULL → JMP [[RCX]+0x368]
03070A40   NULL回退 → JMP 03070A48 普通接收器
```

构造器 `03051F6C` 清零 EDI，`030520DE` 用它把 `member+0xD08` 初始化为 NULL；动态何时改写 `+0xD08` 未证明。**相同 +0x368 槽不保证进入同一具体成员接收器**。但这并不能证明玩家 Shift 折返命中特殊转发，或它造成挤压。

## 4. 否证、边界与下一轮单一目标

- 不再把 post-steering `+0x90` RNG 写或者空间边界构造器视为士兵坐标更新。
- 不再把特殊子对象位置同步无条件认作普通步兵持续积分。
- `context+0x1D8 virtual+0x10` 的**具体对象类型、虚表目标及最终运动写者尚未闭合**；玩家 Shift 物理挤压的错误数据条件依然未知。
- 离线证明不能代替实例级、同阶段世界目标与真实位移因果。
- **下一步优先定型 `03085114` 的 `context+0x1D8` 对象构造器和 `virtual+0x10` 具体目标/写者**。若它不写成员运动，则明确停止此方向，跟普通 Tick 的其它真实写入边，而不是重复 Group 池与 B 多态。

`native_gameplay_patch_authorized=false`。不要求玩家再次证明 Shift 问题，不发布全局 NOP，不动 `main` 或原始 EXE，保留 CA Shift/RMB/ATTACK/渐进转向/避障。
