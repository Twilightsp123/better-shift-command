# BSC Native 静态审计 R36（当前对话第 2 轮）— 三种 B 路线任务与同一 Group 内嵌槽位

日期：2026-10-17。只读分析《Total War: WARHAMMER III》新版 Win64 `Warhammer3.exe`，SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`，232,531,920 B，ImageBase `0x140000000`。地址均为 **RVA**，不等于 ASLR 实际加载地址。本次没有读写游戏进程、没有补丁，也没有玩家实机新证据。

## 1. 本轮新事实：B 不是一种统一的实例类型

在固定新版 EXE 的 `.udata` 和虚表数据上，逐一复核了**真正的构造器虚表写入**、具体 `+0x10` 方法及直接调用者：

| B 实现 | 构造器 | 虚表 | 虚表 `+0x10` 方法 | 实际下游 |
|---|---|---|---|---|
| B1 路线推进 | `0x03268920` | `0x03AE5820` | `0x03286288` | 进入 `0x032862C4` 做路线记录条件检查、释放或重新生成；该方法及被调用者**无直接**逐成员发送器 E8 |
| B2 成员发包 | `0x03268D34` | `0x03AE5800` | `0x032863A0` | 满足 `+0x80/+0x78/route+0x08` 等门槛时，`0x03286445` E8 调用 `0x0326A994` 按 Group 成员遍历并调用 `member vtable+0x368` |
| B3 另一任务分支 | `0x03268E3C` | `0x03AE57E0` | `0x03286480` | 条件性 `0x03286572` E8 到 `0x0326B0C8`，后者创建独立任务并走间接方法 `+0x48`；**不能因此称它直接发同一种成员 packet** |

B1 构造器在 `0x0326893F/46` 安装真实虚表，B2 在 `0x03268D45/4C`，B3 在 `0x03268E54/5E`。重新扫描新版可执行代码的 `E8`，每个构造器都只检出**一个**直接调用入口，分别是 `0x0327ED3C`、`0x0327EDD5`、`0x0327EE65`；调用点属于各自独立的分发函数 `0x0327ECA4`、`0x0327ED4C`、`0x0327EDEC`。这些具体原码已经做调用位移及 GNU objdump 指令起点复核。

**纠正前轮边界：** 第35轮将 `0x03AE5800` 虚方法对应的 B packet sender 视作独立且缺实例来源。本轮新增 `0x0327ED4C→0x03268D34→0x03AE5800→0x032863A0→0x0326A994` 的完整静态类型链。仍然**不能**把它直接等同于第35轮短任务发包 `0x0327ECA4` 在同一次调用栈中一定会执行的过程。

## 2. 同一 shortTask 回调有两个互斥的 B 相关状态通道

新版原始回调 `0x02F5B1E4`：

```
getter 大任务存在，bigTask+0x20 == 4
 ├─ bigTask+0x24 != 0
 │    -> shortTask 组装记录
 │    -> 0x02F5B3F9 重新读取 [UnitRoot+0x32F8] 当前 Group
 │    -> 0x02F5B400 / 0x0327ECA4
 │       -> A 条件直接发送，或 B1 任务构造（根据原生模式判断）
 └─ bigTask+0x24 == 0
      -> 0x02F5B463 读取 bigTask+0x28
      -> 等于 3 时 0x02F5B475 E8 0x02F54510
      -> 0x02F54527 E8 0x02F55FE0 条件释放原 slot 大任务引用
      -> 0x02F54621 重新读取 [UnitRoot+0x32F8] 当前 Group
      -> 0x02F54628 E8 0x0327ED4C
         -> A 条件直接发送，或 B2 任务构造（根据另一原生模式判断）
```

**两条分支在单次回调中互斥，不是一次调用连续发送两套 B packet。** 同一个 shortTask 经过多次调用是否跨越这些状态、游戏实际 Shift 命中哪个门槛、转换期间 Group 是否发生错误替换，均没有实机证据。

另外 `0x0327EDEC → 0x03268E3C` 的 B3 来自其它直接调用者（例如 `0x0302B2B0`）；目前没有将它错误绑定到上述同一个 shortTask 后继路段。

## 3. 三个分发入口共享的是目标 Group 的内嵌任务槽位，不是同一条路线

三个分发函数在 B 分支的构造调用处，均先以当前传入的 Group 定位 `Group+0x8F0`，调用 `0x02F3F0FC` 进行旧任务状态清理，再以 `Group+0x8F0+0x18 = Group+0x908` 作为新 B 实例地址：

- B1：`0x0327ED1E / 0x0327ED2D / 0x0327ED3C`
- B2：`0x0327EDB3 / 0x0327EDBF / 0x0327EDD5`
- B3：`0x0327EE47 / 0x0327EE56 / 0x0327EE65`

清理器 `0x02F3F0FC` 在 `0x02F3F10A` 检查 `parent+0x118 == 1`；**仅该条件成立**时经 `0x02F3F11B` 调旧对象的虚析构，之后清理 `parent+0x118/+0x119` 状态标记。不能把清理函数被调用就说成旧 B 任务每次都被真正析构。这里也不存在已证明的路段 generation 校验屏障。

B1 的 `0x032862C4` 内部真实可见对 `B1+0x58` 路线对象、`+0x20` 引用和 `+0x60` 状态的条件处理，在 `0x0328637B / 0x0328638A` 选择不同的路线求解调用并更新 `B1+0x58`。这与 B2 用 `+0x78` 作成员发包准备的时相不同。

## 4. 对假设的收窄和停止条件

**本轮新增的是可追踪的 B 实例类型及 phase gate，不是根因证明。** 不能以这三种任务在同一 Group 的可变槽位为由，直接断定出现了越代、重复发包或异常目标；CA 可以合法地在不同状态替换同一内嵌任务。

下面这条假说才有资格进入下一步：*同一次 Shift 后继 MOVE 的 bigTask phase 从 B1 对应的条件变化到 B2 对应的条件时，是否存在旧 Group 目标尚未结清、新成员目标已被覆盖的真实重叠窗口？* 需要进一步从具体任务有效性、目标提交（`member+0x1E0`）及已定型的世界目标解析追踪；如果无法证明同实例转换条件或输入错误，就停止扩张 Group 调查，转而寻找 steering 物理速度/位移输出写者。

**严禁：** 将三种虚方法统称为 B fanout；把原生 `+0x24/+0x28` 条件当作玩家 Shift 键标志；只凭指针相等宣称相同对象生命周期；全局 NOP 成员位置写者、替换原生 Shift 或修改 RMB/Shift ATTACK。
