## 真正重新验证过的调用关系

新版 MOVE 工作 `0302AE74` 中 `0302AF95` 与 `0302B126` 两处 E8 都指向 `030179B0`；`0302B1B3` 的 E8 指向 `02F31778` shortTask 构造器。

新回调 `02F5B3F0 → 02F5B3F9` 依次读取 `task+0x08` 的 UnitRoot 和 `UnitRoot+0x32F8` 的当前 Group，并通过 `02F5B400` E8 到 `0327ECA4`。该分发器 A/B 的实际 E8 目标分别是 `030DA5D8` 和 `03268920`。

新版 `030782CF` E8 → `03163DC4`，`030785B5` E8 → `0316460C`；成员 Tick `03087349` E8 → steering `03059BC8`，其 `03059DF7` E8 → 邻兵候选 `030679CC`，`0305A800` E8 → 接触响应 `03085114`。

## 静态审计数值（新 EXE）

- 29 个受限函数范围独立重绑定。
- 从仓库 R32/R33 及已审计 steering/neighbor/queue 清单抽取去重后的 **318** 条旧指令位置：**318/318** 新 PE unwind 函数所有者 + GNU objdump 指令起点。
- **281/318** 字节保持一致；余下 37 是 E8 相对位移或 RIP 相对 LEA 编码变化，**不能记为原字节一致**，没有其他未分类 opcode 差异。
- **35** 处新版直接 E8 调用被重新解码，其中 **18** 条有双方已重绑定的地址可直接确认目标等价；其余目标属于尚未充分 rebasing 的函数，不应把“已解码”说成“全边已闭合”。
- **11/11** 个受限分支目标均与各自重绑定预期一致。
- 本地含新版原始 EXE **9/9 unittest PASS**，且审核器错误 SHA 拒绝运行。
- 实际新版玩家游戏内动态命中：**未测试**。

## 关键安全限制

1. 新版 `member vtable+0x368 / +0x100 / +0xE8` 三槽目标组合在 **28 个**不同数据表候选中均可成立，不能靠这三个槽宣布某个旧成员虚表是新版唯一对应表；需构造器、对象类型和 RTTI 进一步确认。
2. 旧 V3 实机证据不能说成“新版实机已经命中”。
3. 静态可达不证明实际 Shift 折返错用 Group/route 代际，不证明异常士兵坐标写入或 steering 根因。
4. 禁止用这些 RVA 直接作为未经 Windows 进程安全审核的 Hook，禁止全局 NOP 位置写入或更改 RMB、Shift ATTACK、寻路。
5. 本轮 **没有 native gameplay patch**；`main` 不动；不上传游戏 EXE。
