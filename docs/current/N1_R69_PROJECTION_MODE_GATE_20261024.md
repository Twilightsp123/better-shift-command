# BSC R69 — 成员模式清零与投影重建的原生静态边界（2026-10-24）

**证据等级：当前真实 WH3 EXE 静态证据。不是同一次玩家 Shift 命中、不是 Windows 运行测试，也没有可安装的 Native gameplay patch。**

## 精确文件身份与测试
Windows x64 Warhammer3.exe，SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`，232531920 字节，ImageBase `0x140000000`，以下均 RVA。本轮本地独立验证 **76/76 整条真实指令及 GNU objdump 指令起点、12/12 E8 相对调用目标、4/4 PE UNWIND 函数边界、0.01f 原生 Float32 常量**；本地 **20/20 unittest PASS，含原始 EXE 完整校验**。GitHub CI 不带商业 EXE，真实文件用例应 SKIP。

## 真正闭合的指令关系
1. R68 模式设置器 `0x0307D9C0` 在旧 `member+0x104` 是1/2、请求新模式0时：`0x0307D9D9` 清 `member+0x23C`，`0x0307D9DF` 清 `member+0x1C8`，`0x0307D9E5` 写模式，`0x0307D9F8` 直接 E8→`0x0307DB60`。
2. **`0x0310006C` 是独立的成员运动包装器。** `0x0310009F` 读 `member+0x23C`，`0x031000A5` 将旧值留存到 `+0x238`。在一条有条件路径中 `0x0310014C` 先 E8→真实积分器 `0x03146FF0`，然后 `0x03100233/+247` 用 `member+0x1E0` 目标记录调用 `0x03121F54` 解析带参考框架的世界目标；`0x031002A8` 按运动对目标方向投影，或 `0x031002CF` 按运动向量模长，写回 float32 `member+0x23C`。这些重算受门槛约束，不能宣称每帧发生。
3. **`0x0307E1A0` 又是一个单独的 PE 函数**，不是 `0x0307DB60` 的连续代码尾部。它在 `0x0307E1CE` 读原生 Float32 0.01（真实值0.009999999776482582）；`0x0307E1D6` 比较该值与同一成员 `+0x23C`，`0x0307E1DD` 的 JA 在 0.01 大于成员值时跳过一段后续状态处理；此外该函数还在 `0x0307E306/+33C` 消费 `+0x23C`。这证明字段有实际控制流作用，**不证明这是 Shift 专属减速/停止判断**。
4. `member+0x1C8` 的**同一执行实例后继读取尚未核实**。不要因为 `+0x1CC` 与朝向相关，就把相邻字段混同。

## 最关键的断点与止损
- **已证**：模式1/2→0 会清零投影字段；存在独立的投影读、后续条件性重建及 0.01f 状态门槛。
- **未证**：`0x0307DB60` 何时/是否对同一个成员调用上述两个独立函数；普通 Shift 后继 MOVE 中是否真的发生该时序；清零是否产生异常转向、挤压。
- 本轮没有合法补丁候选。**禁止 NOP 清零、强行同步 `+0x104`、修改 0.01f、调高所有士兵速度。**
- R70 严格限于一项：证明某个同对象的调用现场真正串起模式清零→投影消费者／重建；如果仍无法证明，**关闭此静态假说为 SHlFT_CAUSAL_LINK_BLOCKED**，不再无限搜索相同 offset，转到有线程生命周期保护的有限只读观测设计。
