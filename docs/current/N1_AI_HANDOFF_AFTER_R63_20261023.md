## 4. 已确认的重要原生路径（当前 SHA 的 RVA）

### 4.1 RMB 与 Shift 的命令入口

- 统一 MOVE 接口：`0x030374CC`；`R8` 为 MOVE 命令描述符，`R9B` 控制队列语义。**R9B=0 是替换、非0是追加；R9B 不等于玩家 Shift 键位**（引擎内部/AI 同样能追加）。
- 后继 MOVE 工作：`0x0302AE74`；路线配置器：`0x030179B0`；shortTask 构造：`0x02F31778`；shortTask 回调 `0x02F5B1E4`；晚绑定当前 `UnitRoot+0x32F8` Group 的指令约 `0x02F5B3F9`；Group A/B 分派 `0x0327ECA4`。
- 同一个后继 MOVE 依据 `MOVEslot+0x9A bit0x02`，选 `slot+0x98` 预存朝向，或根据 live Group 空间位置与目标计算朝向，两者进入**同一个**路线配置器。不可直接全局改 bit2。

### 4.2 阵型投影与原生平滑折返候选

- 路线描述符构造器 `0x030F1B3C` 只是复制坐标、朝向 `+0x38`、空间参数，不是曲率求解器（R54 纠错）。
- 路线转换器：`0x03102B28`，与旧版 `0x030FDA9C` 为重绑定关系；不是“新找到的另一个求解器”。
- Group 的 `+0xB30` 指向多态阵型空间策略（可能指向内嵌 `Group+0xA30`），多种方法用排列维度、成员数量和间距计算跨度。**不是已证明的转弯半径**（R55）。
- 16-bit 角度查表 `0x03E8F360` 由实际初始化例程写入三角方向值。阵型投影可以写成 `P=C-(A-B)/2 · V(theta)`，但空间参考 `C` 也可随引用框架变化；朝向跳变不必然导致物理位置跳变（R56）。
- `0x0310E450` 含有条件的参考角 `±0x4000`（±90°）分支，不是已证的 Shift 专属 180° 自动拆分器（R57）。它经 `0x030FA978` 把派生侧角写到**栈上临时路线记录 `+0x44`**。禁止直接改 `0x4000` 或全局锁转弯侧。
- `0x03114BF4` 真正消费记录 `+0x44`，使用 sin/cos 方向表，将候选工作对象 `work+0x1A8/+0x1AC` 变成空间候选点，附带方向字段；不是 member 目标的直接写入（R62）。

### 4.3 R63 最新进展：候选记录与路线对象

**这是下轮真正的起点，R63 比 R62 更新，切勿回退到 R62 重做。**

R63 已以新版真实 EXE 静态证实：

```text
0x03102B28 route converter
  ├─ 经 0x0310E450 / 0x030FA978 生成派生侧角（条件性）
  ├─ 0x03102E14 取得候选容器 0x04367228
  ├─ 0x03102E27 把容器作为 Win64 第六个实参
  └─ 0x03102E38 CALL 0x0312AAC4 candidate generator
       ├─ 0x0312AAEF 从 [RBP+0x508] 取回同一容器，R14 保存
       ├─ 0x0312AB99 CALL 0x03114BF4 形成 work 候选几何
       ├─ 0x0312ABA5 的 AL 分支门槛
       ├─ 0x0312B060 CALL 0x030C72F0 生成栈上候选记录 [RBP+0x1E0]
       └─ 0x0312B6C4 / 0x0312B6CE CALL 0x030EE9BC
                                向 R14 所指相同候选容器追加记录
```

候选容器 `+0x00` 为容量，`+0x04` 为记录数，`+0x08` 为数组指针；**记录步长 `0xD0` 字节**。`0x030EE9BC` 经 `0x030C71E0` 复制字段到 `+0xCC` 并增加 count。`0x03102E48/+0x03102E4E` 检查候选数；有候选、其他门槛满足时使用：

`0x03121498 → 0x030C7058 → 0x030CC8E4`

构造路线对象，转换器最终某些分支可返回对象，`0x03126B46` 的上游 node 构造器可把结果存入 `node+0x70`。此前 R37/R62 已将 B2 `+0x60` 与 route node，以及 B2 发包器 `0x0326A994` 建立条件性代码关系。

**R63 绝对没有证明** `work+0x1A8/+0x1AC` 那个特定 ±90° 点确实被写入同一条最终保留的 `0xD0` 记录、被选中、成为 B2 成员 packet，也没有证明玩家 Shift 实际发生选侧翻转。工作对象与候选记录是不同对象类型，不得仅凭字段偏移宣称直接复制。

R63 报告的验证等级：90/90 原始指令与真正起点、13/13 E8、6/6 跳转、31/31 类型化操作数；本地 21/21 测试含原始新版 EXE PASS。这是**报告中记载的离线结果**；若没有拿到其审计器/EXE，下一 AI 不得冒充亲自重跑。

### 4.4 成员世界目标与运动积分（已类型化）

- B2 成员发送器 `0x0326A994`（条件分支）；成员 packet 接收器 `0x03070A48`。A/B、mode、内嵌任务及虚表 `+0xE8/+0x100` 决定不同接收和更新阶段；不是“收到同一包就同一帧同步运动”。
- 普通成员 Tick `0x03086F04`，steering `0x03059BC8`，世界目标解析器 `0x03121F54`；成员目标提交 `0x0311E5DC`。`member+0x1E0` 为目标记录、`+0x1F0` 可能关联坐标参考对象；必须比较实际解析后的**世界目标**，不能直接对比局部字节。
- 普通成员真实位移积分 `0x03146FF0` 经成员 `virtual+0x20` 等入口执行，已确认写 `member+0x88/+0x8C/+0x90` 与 `+0xE0/+0xE8`，处理待积分增量 `+0x13C/+0x140/+0x144`。动作状态 `member+0x108` 与 `+0x155` 控制条件分支。R41/R42 已查过，别重回“还未找到普通士兵位移写入器”。
- R43/R44 有多种目标+运动输入安装方法、逐成员延迟与 state16；B2 packet **没有被证明直接创建 R44 的 state16 缓存向量任务**（R45）；旧延迟 packet 并非默认导致重复发包，R61 发现间接取消链 `member+0xE8 → 0x03078268 → 0x0307AE84 → 0x02DB5AC4`，需满足模式条件。**降级/停止无证据的全局旧包残留猜想**。
- R40 已将 `steering→0x03085114→context+0x1D8 virtual+0x10` 定型为事件分发链，已知订阅者把事件放入队列，不是已证的直接物理速度写入器；不能重复沿这条外侧路径无限找函数。
