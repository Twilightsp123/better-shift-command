# Better Shift Command — R91 接触订阅者的即时/暂存分发边界（2026-11-01）

## 0. 核心结论与范围

**R91 真正的新机制：** R89–R90 已将 `member+0x58 → C+0x440 → G+0xF0 → P+0x1D8` 的有界构造来源与接收器虚表联系起来。R91 在同一个精确版本原始游戏 EXE 中，进一步证明该事件接收器不是简单“收到后立即通知全部订阅者”：它存在 **条件即时回调 + 暂存 0x38 字节记录 + 独立队列回放/清空** 两条路径。

本轮**没有**找到一个能够从注册代码证明实际类型的接触订阅者；没有证明回调会修改同一名士兵的 `pending +0x13C/+0x140/+0x144`、实际 `XYZ +0x88/+0x8C/+0x90` 或导航目标 `+0x1E0/+0x1F0`。条件性的暂存也**不证明跨帧/跨 Tick 延迟**，必须先找到谁在什么时候调用回放函数。未进行 Windows gameplay 动态测试，不提供 Hook 或可玩补丁。

原始文件：`Warhammer3.exe`，大小 `232531920` 字节，SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`，Windows AMD64，PE ImageBase `0x140000000`。下文地址均为 RVA；公开仓库不上传 EXE。

## 1. 修正 R90 后对接收器虚表的精确认识

在 P 构造器中，`0x02DA09DC` 初始化 `P+0x1D8`，并于 `0x02DA2107/0x02DA210E` 将最终虚表 `0x03AB1B48` 写入该内嵌子对象。虚表中：

| 接收器 vtable 项 | 解析到的原生 RVA | R91 审计含义 |
| --- | --- | --- |
| +0x00 | `0x02DC9564` | 遍历 `this+0x38` 暂存记录、再次按订阅者筛选分发、最后清零 `this+0x34` |
| +0x08 | `0x01196574` | adjustor thunk：`this-=0x1D8`，再跳向 `0x02DAD91C`（与宿主对象回收相关，但需审计其完整语义） |
| +0x10 | `0x02DD06F0` | 接收新记录、即时分发或暂存 |

早期虚表 `0x03AAF7F0` 的 +0x00 和 +0x10 也是上述两个分发方法，只有 +0x08 目标为 `0x02DACF54`。全文件 PE section 8 字节对齐无假设的精确指针搜索，`0x140000000 + 0x02DD06F0` 只在 RVA `0x03AAF800` 与 `0x03AB1B58` 发现两次（它们恰好为上述两份虚表的 +0x10 槽）。这是静态指针命中统计，**不证明没有运行期动态构造的其他虚表**。

**关键身份纠错：**接收器 vtable 的 +0x08 是调整 `this` 的 thunk；`0x02DD0763` 调用的**订阅者** vtable+0x08 则属于另一个对象的接口，二者不可混同。

## 2. 记录即时分发与暂存的原始控制流

`0x02DD06F0` 接受 `RCX=this(=P+0x1D8)` 和 `RDX=接触记录`，在 `0x02DD070B` 保存 RDX 到 R14。以 `this+0x0C` 为订阅者数、`this+0x10` 为订阅者指针数组，逐项读取订阅对象。

- `0x02DD0753` 通过订阅者 vtable+0x10 得到一个 AL 判别值。
- `0x02DD0758 JE→0x02DD076D`：该返回值为 0 的分支**不**在这个循环位置调用其 vtable+0x08，且 `0x02DD076D MOV BPL,1`。
- AL 非 0 时，在 `0x02DD075D` 把原记录指针传给 `RDX`，`0x02DD0763` 才调用该订阅者 vtable+0x08。
- 若 BPL 最终为 1，`0x02DD078C LEA RCX,[RDI+0x30]`、`0x02DD0790 MOV RDX,R14`，`0x02DD0793 E8→0x02D8E774`，进入暂存记录向量追加。

以上只是**分支的静态规则**，不是已证的 listener “优先级/线程/时间阶段”定义。

## 3. 暂存向量的真实记录大小与回放

`0x02D8E774` 把第一参数看成一个动态容量、数量、数据指针向量（`+0x00/+0x04/+0x08`）。它通过 `0x02D8E7AD IMUL ...,0x38` 计算扩容字节量，逐项复制接触记录，并在 `0x02D8E914 INC [RBX+0x04]` 递增记录数。分支里涉及标志位拷贝与调整，因此不应夸张称“纯无条件 memcpy”；明确的共同结构大小为 **0x38 字节**。

`0x02DC9564`（同一接收器虚表 +0x00）则以 `this+0x34` 为暂存记录数，以 `this+0x38` 为暂存记录数组起点：

- `0x02DC9583 IMUL RDX,RAX,0x38` 将记录数转换为末尾地址。
- `0x02DC95AA` 再调用订阅者 vtable+0x10 判别。
- `0x02DC95AF JNE→0x02DC95BD`：**AL=0 时**通过 `0x02DC95BA` 订阅者 vtable+0x08 派送本条暂存记录；AL!=0 则本处跳过。
- `0x02DC95D4 ADD RDI,0x38` 切换到下一条记录；`0x02DC95E5 AND DWORD PTR [RBX+0x34],0` 清零暂存数。

这同时纠正了一个容易误读的推断：同一订阅者接口 `+0x10` 在**新记录路径**与**暂存回放路径**中存在相反的回调门槛。不能把它简单命名为“订阅是否有效”的布尔属性，也不能称这些事件已经导致士兵发生物理位移。静态代码没有说明何时调用 +0x00 或是否跨 Tick。

## 4. 可证与不可证：因果止损

当前可证的是：在已经类型化的 P 子对象内，接触记录可以按订阅者虚方法返回值走即时传递或变成暂存记录，另一个虚方法能按 0x38 字节步长将暂存记录再次派送。接收器的这一控制流中**未看到写普通 member motor 字段**。

当前**不能**从事件队列推导：某个 Shift 转向时多个士兵都收到这些事件、记录在跨帧排队、订阅者对士兵运动进行了避障修正、队列引发兵牌挤压或清空队列能够改善挤压。

R91 在限定范围内核对了 P 子对象早/晚虚表及分发/回放/记录追加，没有找到满足“实际订阅者注册、同一个 member、同一个接触记录指向 motor 写入者”的完整链。就此按 R90 要求**止损**，不再扩大无对象身份支撑的广播函数查找；下一轮优先回到 **同一兵牌成员目标 / 转向阶段 / 参考框架 / 实际位移同步**。若将来找到特定订阅者注册证据，再重新打开接触事件通道。
