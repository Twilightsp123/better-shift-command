# BSC — 成功判据与停止条件（2026-11-05，R92 后约束）

**强制原则：** 原生 RVA、机器码数量、构造器/事件订阅者数量、CI 通过、合成运动学测试，不是找到挤压根因，也不是 gameplay 修复成功。缺陷存在由玩家多次实机确认，无须重新证明。

## 一句话最终成功定义

修改 CA 原生 Shift 连续 MOVE 的一个有证据支持的局部原生判断/目标生成/运动协调机制，使同一兵牌急转和连续 180° 折返的异常互相穿插、挤压得到实质改善，同时保留原生全部 Shift 路点、渐进曲线转向、避障、普通 RMB 以及 Shift ATTACK，不用 Lua 重发 MOVE，不以禁用移动/全局降速/强制统一朝向为代价。

## 三种绝不能混淆的状态

- **SEARCH_CANDIDATE**：找到了具体的原生候选分支及对象字段的完整来源，能提出明确条件与可证伪结果；尚未证明实际 Shift 触发和异常因果。
- **ROOT_CAUSE_PROVEN**：同一个 UnitRoot、同一个 Shift 任务/路线段、稳定 member identity、相互一致的时间样本中，证明候选分支命中；其造成目标/阶段/运动中的**第一个异常分歧**；通过对照或受控干预排除了单纯的关联，而非只展示“同时出现”。
- **GAMEPLAY_FIX_PROVEN**：在 ROOT_CAUSE_PROVEN 基础上，有原生最小可逆补丁；原版与补丁在同一 Shift 场景的可比观测符合已预注册的异常空间挤压改善指标，且所有保留功能回归通过。

**只有 SEARCH_CANDIDATE 的场景绝对不能把 `root_cause_proven` 或 `gameplay_fix_proven` 写成 true。**

## 搜索成功（不是修复成功）的最低证据包

候选必须具备全部内容：

1. 精确版本：EXE SHA256/PE/指令字节/LLVM 指令起点/函数边界；有明确的输入对象类型和字段所有权。
2. 精确控制位置：RVA、原始条件、读取字段、分支 A/B 的状态差别，以及最终写入或决策对象。可选目标只包括原生 Group 目标生成/slot 路径、成员转向阶段决策、局部 Steering/物理写者协调。
3. 具体同实例链接：原生 queued Shift -> Root -> Group -> member ID -> route/leg -> 目标/状态/实际 XYZ。不能用相同上下文偏移、同一函数名或独立调用链代替身份和时间证据。
4. 第一个异常分歧：以同一时刻至少两名同兵牌成员的参考框架已解析 world goal、阶段/朝向、速度/pending、XYZ 与空间间距为序，指出**哪个变量先**发生不合理差异，哪个后果随之发生；应有至少一个未触发异常的负对照。
5. 因果判别设计：改动某个**确定的谓词/目标输出/交接条件**会产生什么可测的差别；未经安全受控验证不可把修复假说提升为根因证明。

缺少 3/4 的搜到再多 RVA，只能作为静态背景，不算成功搜索。

## 三类可接受的修复靶点

- A. **Goal divergence**：同一原生路线段的目标生产/世界参考框架转换导致不合理成员目标汇聚。修复只针对具体原生目标计算/策略，不能直接全部改成固定槽位换位。
- B. **Phase divergence**：目标合理但同兵牌成员进入下一阶段的相位/时机不协调。修复针对可确认的 Group/成员阶段协调谓词；不应简单等待最后一个落后成员，也不能让整个单位逐个路点停车。
- C. **Motion divergence**：目标与阶段正常，然而 Steering、A 类 packet XYZ 写者、积分器等产生实际轨迹异常。先在真实同一 Shift tick 上证实写者调用、先后顺序和同一个成员身份；不能因为发现两套 XYZ 写者就宣称竞争。

R77 固定索引并非必然拥挤，R78 的 A Packet 未证属于普通 Shift 持久导航目标，R79 的 0.01f 不是已证路段到达阈值；这些禁忌继续有效。

## Patch 前审查门槛

必须具备原始函数边界/ABI、对象生命周期、线程所有权、SEH/unwind、Hook 与 Derpy/Memreader 的冲突检查、失效即停回滚设计。未通过任何一项，不许安装到游戏，也不能向用户要求盲测试。不得更改 main。

## 两次用户实机会话的测试制度

**测试 A（综合基线，仅一次会话，前置条件达成才安排）**：一个可复用的只读观测器同时记录原生任务/路段、Group/member、local+world goal、参考框架、成员动作/运动状态、速度、pending、XYZ、A/B分支与真实 XYZ 写者命中。一次会话包括 RMB、Shift 90°、Shift 180° 连续折返及 Shift MOVE→ATTACK；这些都是针对因果假说的采样，而不是再证明缺陷存在。

**测试 B（补丁对比，仅一次会话）**：只有 A 已形成受限的原生修复候选且安全门槛通过才启动；同样场景的 patched 与可比 baseline，检查成员穿插/严重近距持续程度、路径与阶段连续性、避障、RMB、Shift ATTACK。可在同一会话按固定脚本进行多个子场景，但不额外要求用户反复实机。

若不能可靠得到实际成员体型/碰撞阈值，不允许把任意的模型数学距离当成实际“碰撞”。可先展示同时刻最近距离分布和非邻接成员空间顺序交换、时序、用户可确认画面；改善标准/容差必须在补丁试验之前基于真实基线和可用几何数据登记，不能看完结果后补设阈值以宣布通过。

## 研究停止规则

- 找不到可信的 Shift 同实例身份与安全只读观察条件：停止要求玩家测试，只做有界静态逆向。
- 没有具体订阅者与同成员运动写入边：停止无限追 R91 接触事件广播。
- 找不到可改变的局部决策和反事实：不能宣称发现根因或动手 patch。
- 找到可疑地址但无同实例证据：标记 `SEARCH_CANDIDATE`，给出仍缺的**一个明确证据对象**，不得以更多函数数量当作进展。
- 已验证补丁但损坏原生路径、避障、RMB 或 Shift ATTACK：`GAMEPLAY_FIX_PROVEN=false`，直接判失败。

每次汇报必须列出 `SEARCH_CANDIDATE / ROOT_CAUSE_PROVEN / GAMEPLAY_FIX_PROVEN` 三项真值及本轮是否解决了哪一个必要证据缺口。维持 R92 所定两次实机上限，不经用户许可追加。
