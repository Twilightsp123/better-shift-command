## Finding A — status source `related_state+0x240` is task-collection count

Former [N1_903_MOVE_STATUS_CHAIN.md](N1_903_MOVE_STATUS_CHAIN.md) identified VTable[+0x10] at `0x030440F8`: it sets MOVE object's `+0x20` status from whether `[related_state+0x240] == 0`.

New source instruction facts:
- `0x02F2FFB0` adds a collection entry at `state+0x200 + index*0x10`, increments `state+0x240` at `0x02F2FFDF`, and adjusts `+0x244/+0x248` accounting.
- `0x02F4FD5C` conditionally releases collection entries and decrements `+0x240` at `0x02F4FDC4`.
- `0x03043520` iterates entry pointers, calls virtual methods, and decrements `+0x240` at `0x030435FF`; it tracks `+0x250/+0x251/+0x254` lifecycle/control fields.
- Original MOVE virtual [+0x08] `0x03025D70` calls that collection-append helper at `0x03026091`, passing its own `object+0x18` pointer as the collection object. VTable [+0x10] later checks its count.

**Conclusion:** `+0x240` is an outstanding entry count in an auxiliary native task/suborder-like collection, **NOT an arrival-radius or speed field**. Exact task-domain semantics remain open. Do not force the counter/status to zero.

## Finding C — a conditional native successor transfer exists

In original order processor `0x0304433C`, with queue count >1 and other native preconditions:
1. Active object virtual `+0x40` returns non-null pointer (`0x03044562`).
2. Next ring slot computed with 40-entry wrap; next object virtual `+0x38` must approve (`0x03044596`).
3. Next object virtual `+0x48` receives returned pointer (`0x030445AB`).
4. Native ring pop at `0x030445B1` → `0x02F4FD10`, then collection cleanup at `0x030445BC` → `0x02F4FD5C`.
5. Normal continuation invokes `0x030433B0`, which may independently complete/pop an order.

Recovered MOVE VTable `0x0390B4F0`:
| Virtual offset | RVA | Observed meaning |
|---|---|---|
| +0x08 | `0x03025D70` | submits auxiliary work under native branches |
| +0x10 | `0x030440F8` | finished status from task count==0 |
| +0x38 | `0x008D3350` | `mov al, 1; ret` (eligibility true for this MOVE type) |
| +0x40 | `0x03039FB0` | returns special object at MOVE+0xA0 only if its state is suitable; else null |
| +0x48 | `0x03040864` | constructs/attaches native task/state using order data and passed pointer |

`0x03039FB0` checks non-null MOVE+0xA0, `state+0x20==4`, other flags and another validator. Therefore **the special transfer branch cannot be declared universal Shift MOVE→MOVE lookahead**; extension is neither justified nor authorized without proving semantics, thread safety and negative REPLACE/HALT controls.
