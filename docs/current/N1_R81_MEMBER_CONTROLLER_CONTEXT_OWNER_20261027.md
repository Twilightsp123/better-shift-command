# BSC R81 — 原始成员控制器初始化、输入记录与跨类型假写者（2026-10-27）

**阶段：用户当前原始 Win64 游戏 EXE 只读静态逆向，非 Shift 挤压根因确认。** 问题是一个兵牌中士兵的群体运动相互穿插，不是某个特定动作代码。本轮没有游戏 Hook、玩法补丁、实机录制，也不要求用户重复测试。

## 一、同一个 member 内嵌控制器的精确初始化来源

当前原生普通士兵构造函数 `0x03052BA8` 在 `0x03052CA0` 调基础初始化 `0x030F31D8`，再按同一个 RBX 成员指针操作：

- `0x03052F62 MOV RAX,[RBX+0x58]`。
- `0x03052F66 MOV [RBX+0x718],RAX` 与 `0x03052F6D MOV [RBX+0x720],RAX`。**构造时两字段均接收 member+0x58 当时的同一上下文值**。不要把 `member+0x718` 这个内嵌子对象误认为 `[member+0x718]` 指向的“另一个 controller 对象”；该内嵌对象起点就是成员内部地址。
- `0x03052F82` 把 `member+0x738` 置零；`0x03052F89` 置零的是相邻 **`member+0x740`**。两条原始码不同，不得混淆。
- R80 的输入 `RCX=&member+0x718` 在 `0x0311F34C` 读取 `controller+0x08`（即 `member+0x720`）再经 `+0x440/+0x160` 选管理器；读取 `controller+0x20`（即 `member+0x738`）所指对象的 `+0xA0` 候选选择参数。

**边界：**构造时的 `member+0x720 == member+0x58` 不证明游戏运行期间一直相等，更不证明它等于某次原生 queued MOVE 的 `UnitRoot+0x38`（或者具有相同路线 generation）。从字段路径形式相似推断对象相同，属于跨类型错误。

## 二、真正的成员候选输入记录的初始化

- `0x0305313C/14C/178` 按构造常量初始化 `member+0x910/+0x914/+0x918` 三维分量。
- `0x0305315C/163/16A/171` 把 `member+0x920/+0x928/+0x930/+0x938` 指针/引用相关 QWORD 初始化为零。
- 后续 `0x030771EC` 把 `&member+0x910` 作为第四参数交给 `0x0311F34C`，后者在 `0x0311F3DB` 可读取输入记录的 `+0x10`（对应 `member+0x920`）作为候选引用。**只证明初值和消费者，不证明该引用在之后始终是 NULL**。
- 独立普通成员方法 `0x0308A2F8` 在本成员 `+0x2E0` 为空时复制本人的 `+0x910/+0x920` 到 `+0xD78/+0xD88`；若 `+0x2E0` 非空，另一条受门槛路径可读取这个关联对象的 `+0x910/+0x920`。同一字段偏移不等于同一对象身份。

## 三、已经排除的两处“member+0x910 写者”假阳性

- `0x03054AD0` 通过 `object+0x168 → context+0x440 → manager+0x150` 得到 RCX，`0x03054B3B` 才写 `[RCX+0x910]`。不是从普通 member RCX 写自己 `+0x910`。
- `0x03086170` 也沿 `object+0x168 → +0x440 → +0x150` 取得 RDX，`0x0308620D` 写 `[RDX+0x910]`。其访问归属另一类管理器对象，**不能纳入成员导航输入运行期写者名单**。

本轮的原码白名单检查还确认 `0x03076F64` 在 `0x030770CD` 与 `0x03077147` **条件读取** `member+0x738`：它可以是非空，存在不同状态分支；本轮没有闭合它的后续同成员赋值者。对 `member+0x920` 也未完成全部间接/宽写入 census。**未定位写者不是“引擎从未赋值”的证据。**

## R81 止损 / R82

**已证：**成员控制器在构造时的成员上下文来源、候选输入初始引用、R80 候选函数读取的正确对象，以及两处同偏移异对象写者误归因。**未证：** `member+0x58` 与同一 Shift 任务 `UnitRoot+0x38` 的精确别名/代际、运行期 `+0x738/+0x920` 的真实所有者及赋值时点、成员之间失当的空间目标组合。

R82 限定审计**一条具体的基础成员上下文→UnitRoot 的类型化所有权边**；若无法建立真实实例等式，标记 `QUEUED_SHIFT_MEMBER_CONTEXT_ALIAS_UNKNOWN` 并停止以偏移同形为理由延伸。另一备选只有在已类型化时才检查 `member+0x738` 或 `+0x920` 的一个运行期写入者。禁止编造同一 Shift generation、强制同步成员 cursor、覆盖目标或部署未审计 Hook。
