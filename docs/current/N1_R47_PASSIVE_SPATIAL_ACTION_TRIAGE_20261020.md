# BSC R47 / 本对话第14轮：不依赖逐成员 Hook 的空间形变与原生动作差分调查

> 日期 2026-10-20。**本轮没有修改或运行 Warhammer III 进程，没有执行 memreader Plus 的原生 DLL、没有安装 Derpy、没有游戏内采样、没有制作 gameplay patch。** 全部结果来自用户上传的新版 EXE 和两份 MOD 的真实静态文件，以及离线合成反例。目标是寻找比连续追 E8/虚表更经济、更能区分根因的调查方法。

## 一、真正的新结论

**1. 独立来源重合的动作虚表足以支持不 Hook 的动作分类。** Derpy 的 `platform.lua` 根据真实对象的 `member+0x330` 查看当前内嵌动作虚表；BSC R38/R44/R45 在同一个新版 EXE 中已定型部分 packet action。R47 直接读取 EXE `.rdata`，核验下列 7 种动作类型的 `virtual+0x08/+0x10` 真实指针，**14/14 槽通过**；另外普通成员 vtable `0x03912950 +0x18/+0x20` 的 Tick 和积分入口，**2/2 槽通过**。

| 离线标签（不把名称当作完整语义） | vtable RVA | +0x08 | +0x10 |
|---|---|---|---|
| Derpy walk_a | `03919350` | `0325F000` | `03264B70` |
| Derpy walk_b | `03AE2400` | `008F9E80` | `03262850` |
| Derpy move_a / BSC B2 special | `039199F8` | `0325E824` | `03263AF8` |
| BSC B2 general | `03919B28` | `0325D9FC` | `03261688` |
| Derpy move_b | `03AE1928` | `0325ECE4` | `032643BC` |

| Derpy melee action | `03AD24B8` | `030813D8` | `030877EC` |

**2. Derpy 的实际源码提供了一个值得检验、但不是本项目已证事实的线索。** 作者在 `P.steer()` 附近注明，实测“regiment walk”没有跟随他直接改写的单人目标点；在 `P.guard()` 附近还记载处于站立的士兵可受到显著位移。此为**第三方作者代码注释中的实机观察**，没有原始数据或独立 BSC 复核；但它提醒我们：`member+0x1E0` 已存目标、`member+0x330` 动作对象、`member+0x88` 实际运动三者**不能未经验证就视为同一个因果驱动层**。R41—R45 的数据流没有必要推翻，只需调整优先级。

**3. 空间形变可以不依赖 Game Group 代际或世界目标解析来量化。** 对两次近时（非原子）快照中相同 ID 的士兵，计算成对 X/Z 距离变化，并对至少 3 个相同成员拟合最优二维刚体平移/旋转（闭式角度拟合）。纯刚体移动不改变成员间距离，因此显著的距离压缩/残差说明采样到的**相对队形发生形变**，但不说明形变一定非法，也不证明 Shift 的根因。

离线比较器还可把空间接近与动作虚表标签并列显示：
- 成员空间相互接近，但动作标签相同：优先回查成员目标分配、局部避障／叠加的整队位移，**不能断言是 steering 错误**。
- 成员空间相互接近，动作标签不同：优先核查 B2 action 与状态切换时相，**不能断言动作不同就是 Bug**。
- 存储的目标发生明显压缩：只能生成**目标层候选**；它不必然是当时真正生效的 motor goal，特别是 `member+0x1F0` 参考对象存在时。

## 二、对旧 R46 原型的实际改进

新增 `bsc_r47_passive_member_sampler_research.lua`，**研究原型，不自动加载、不应直接安装给玩家**：

- 严格要求 memreader Plus `0_13_0`、新版 PE TimeDateStamp `0x6ACEC6F4`；真实 EXE 的静态工具另要求完整 SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`。
- 针对 Derpy 可能先于 F2 安装成员 Tick cave，除了 `hook_info()` 与 `read_original()`，**还检查游戏内存里的当前真实指令字节 `mr.read()`**；`read_original()` 自己在发生补丁后仍可能返回未修改的原码，绝不能单凭它判断无 Hook。还校验 Derpy 修改过的排队动作 Gate 原始字节。
- 只经 `BattleUnit → userdata+0x08 → unit+0xA4/+0xA8` 读取成员数组，且只读取 `0x03912950` 原始普通成员类型；**不把此 unit 对象强行等同 BSC 的 UnitRoot**。
- 每次最多 32 名成员，支持跨整个数组均匀抽样，或指定连续索引窗口；真正的空间邻近由离线距离计算，不以成员数组索引邻近冒充。
- 采集 `member+0x330` 动作虚表标签、`+0x324` 动作状态、`+0x340` 完成状态、`+0x108/+0x155` 标志、`+0x88` 三维位置、`+0x13C` 三维增量和 `+0x1E0` 已存目标及参考对象存在位。不调用原生游戏函数、不写内存、不安装 Hook。
- 读取前后再次比对本 Unit 的存活成员数、数组指针、已选成员指针及虚表；不一致即丢弃。**这只能避免部分撕裂样本，不能保证成员的原子快照或排除 ABA 复用，更不能保证内存并发访问不会导致崩溃。**
- 只输出本会话临时 ID，不写玩家进程指针到日志。没有导出函数调用定时器，也没有实现 MOD 自动加载。**目前没有在游戏内验证 Lua API 调用类型、性能或生命周期安全。**

## 三、离线分析器的精确边界

`r47_spatial_action_triage.py`：

1. 输入 JSONL 每条必须标为 `bsc.n1.passive_member_snapshot.v1`、`sequential-not-atomic`、`inventory_stable=true`，含可匹配的匿名成员 ID、索引及时间。按物理 X/Z 距离（默认起始小于等于 3.5 米）枚举候选成对成员；成员指针/索引不匹配、单位人数变化、非单调时间等拒绝或跳过。
2. 对候选对输出初末距离、压缩比例、当前 action 标签、**线性插值下估计的最小距离**。注意插值假设两次测量同步；仅几何近似，不证明瞬间真的发生碰撞。
3. 至少 3 个身份相同的成员时计算最佳全体刚体平移与二维角度，输出非刚体残差（RMS，米）；与单位整体平移/转向本身区分开。
4. 仅当 `goal_has_reference=false` 且两个 `stored_goal_xz` 均可用时才显示存储目标间距，仍标为 **stored_goal_not_verified_as_active_motor_target**。
5. 禁止原始指针型 ID、NaN/Inf、过量记录；所有输出固定 `first_error_proven=false`、`root_cause_proven=false`、`gameplay_patch_authorized=false`。合成两兵接近反例绝不是玩家游戏数据。

## 四、还有没有其它办法？按实用程度排序

**路线 A（优先，本轮已做出离线工具）：** 利用 memreader Plus 进行低频、非 Hook 的成员快照，离线做空间形变和动作类别比较。能快速分辨该回到动作状态/packet、还是去阵型目标与 steering；不要求用户不断装入不同 Hook。前提是先在严格封闭环境验证实际读取安全，不应立刻投放成 MOD。

**路线 B（同样无需 Native Hook）：** 从已有实机录像（若存在）识别士兵位置轨迹，计算队形刚体残差及局部接近；只需图像数据。但无法得到动作对象、原生目标和成员指针，遮挡、摄影机移动及模型相似性会降低准确性。可以作为与路线 A 独立的非侵入证据，而不是动作因果证明。

**路线 C（只在 A 无法覆盖时考虑）：** 参照 Derpy 的工作线程 mailbox 原理，做单 Unit/有限成员的 C++ 原生环形只读记录；只读 Hook 的线程覆盖不够时才需要。这会安装代码洞、涉及线程重入和补丁跨会话不易回退，本轮没有编写或运行，**不得凭 Derpy 可运行就声称我们的探针安全**。

**路线 D（最终修复思路，不是现成补丁）：** 若目标几何确实冲突，寻找 CA 阵型 slot/成员目标重新指派边界，限定后继 Shift 路段而非全局更改 steering；若目标分配合理、同类动作仍在局部挤压，则寻找局部 steering 与队形约束组合处的最小修补点。任一方向都要通过 RMB/Shift ATTACK 的差异保护，不能根据静态函数地址直接发布。

## 五、独立验证、止损、下一步

- 使用**用户提供的真实原始 EXE + 两份实际 MOD `.pack`** 只读校验：7 个动作类型各 `+0x08/+0x10` = **14/14 指针匹配**；普通成员 `+0x18/+0x20` = **2/2 匹配**；新 EXE 完整 SHA 与两个 `.pack` 的完整 SHA 均固定。
- 本地 **19/19 Python 回归 PASS（含 1 项真实私有 EXE + 两份 MOD 实物核验）**，未提供私有文件时 **18 PASS / 1 SKIP**。离线数学案例验证刚体旋转、队形非刚体压缩、行动分歧、成员身份变更、跨参考框架目标拒绝和边界限额等。
- **Lua 源码仅进行了静态检查；没有 Lua 解释器语法级执行、没有真实 memreader Plus 游戏内执行。**
- R46 的 `BattleUnit→member[]` 是已经由 Derpy 作者使用的对象入口，但本项目没有做过任何游戏内成员采样；必须在准备最少测试时谨慎核查。
- 如果现有 V3 实机匿名位置日志可从仓库或先前档案取得，优先直接喂给新的几何分析思路，**不重复要求用户测试**。目前本次工作空间没有能直接调用的该真实原始 JSONL 数据，所以仅以合成反例验证工具的数学与拒绝行为。
- `main` 禁止修改；无 gameplay 修复、无原生指令写入、无新 DLL。下一轮应首先寻找可以重复利用的历史成员轨迹数据，其次才评估安全且单次的被动采样条件。

**本轮真正新进展是“可用的跨 MOD 动作虚表对照 + 只读空间形变分析工具”，不是另一个猜测性 Shift Native 补丁。**
