# Better Shift Command — Shift 续接下发 vs 成员运动生效的原始机器码审计

**日期：2026-10-11；目标：原始 WH3 Windows x64 EXE（用户标记9.0.3）；SHA256：**
`518c4f292f275142df13b96b9db704a3db7b4870b2c519df83d850596ecc822a`。所有十六进制地址为 RVA，PE ImageBase `0x140000000`。

本轮直接检查用户要求的两个问题：**(1) 成员特定目标转换何时写入实际状态；(2) 所有成员是否同一时刻进入新运动阶段。** 此包全部为只读审计，不含 EXE、DLL、Hook、可安装 Mod。历史 V3 报告对 `0x030D5490` 的 Hook 为 0 命中：本次证实的是**条件调用路径的静态机器码行为**，不能冒充 V3 实际分支执行。

## 1. 当前可证明的“时间边界”

- `0x030D5490`：在**一次函数调用**中先以策略虚表 `+0x48` 生成成员目标记录（`0x030D54CA`），再以 `member[i] → record[i]` 的顺序迭代，复制原生 packet（`0x030D54FC`），通过成员 `virtual+0x368` (`0x030D550F`) 逐个下发，最后调用群组 `virtual+0x20` 后处理（`0x030D5522`）。这段循环**没有等待成员局部任务完成的屏障**。它是顺序调用，不是同一个 CPU 指令瞬间更改全体对象，更不是各模型实际移动同步的证明。
- 常见成员 `0x0306B9F0`：目标转换 `0x0306BA75 → 0x0307F5C8`，在 actor mode=0 分支经 `virtual+0xE8 → 0x03073224 → 0x0315EC98`。在符合其内部分支时，`0x0315F311/0x0315F327` 写 `member+0x88` 开始的位置坐标，`0x0315F33F` 写 `member+0x90`，`0x0315F34D` 写朝向 `member+0xB0`；还调用动作模式/空间维护函数。这是**当前姿态更新**，与“替换以后逐帧行走的主控制器目标”不是同一件已经证明的事实。
- 同一成员接收函数可清理旧的 `member+0x328` 子动作（`0x0306BBAE`）并安装 `0x03914618` 类型的新动作（`0x0306BBD5`）。但是 **`0x03081EB4 → 0x03080F4C` 是成员各自按门控更新子动作**；后者从 `member+0x328` 出发检查它自己的拥有/初始化状态，依次调用动作虚函数 `+0x08/+0x10`，增加局部动作计数。它不会在这个函数内等待全兵牌成员。
- **对象偏移警告：** `0x03080F4C` 输入 RCX 为 `&member+0x328`，故它读取 `[rcx+0x154]` 应理解为相对成员的 `+0x47C`，不是此前普遍称为成员动作位的 `member+0x154`。

## 2. 这条目标包是否立即更换主运动控制器？

**尚无已证明的直接连接。** 对 `0x0306B9F0`、`0x03073224`、`0x0315EC98` 和 `0x03056ED4` 的完整 PE 异常函数边界扫描，未发现直接 `E8/E9` 进入另一套已识别的 `0x03071E04 → 0x03071F20 → 0x0311954C` 目标记录/路线处理链。后者明确有对 `member+0x7F8/+0x818` 的目标记录写入，属于另一条需区分的原生路径。

**负面边界：** 这里的直接调用缺席无法排除虚函数、内部别名、共享状态消费者或异步任务。因此不能推断“绝对没有更换运动目标”；更不能以此推出这些动作必然属于普通 RMB 或 Shift。

## 3. 新的正向交叉证据：原生群组状态也用同一种变换后的成员目标

`0x030D56BC` 调用策略 `+0x48` 生成群组目标数组，然后进入 `0x030D572C`。此函数在 `0x030D579B` **调用与成员接收器完全相同的 `0x0307F5C8` 目标变换**，从成员 `+0x88/+0x90` 当前 X/Z 计算目标距离。它既计数离目标较远的成员（`group+0xD0C4`），也计算**活跃成员的平均距离**；平均距离低于输入阈值时更新 `group+0xD0B8` 的时间戳。

所以这一个度量**不是全体成员逐个达到精确终点的判定**。离线反例：四名成员距离 `[0,0,0,4]`，平均为1，阈值1.5时可触发均值条件，尽管仍有一名距离4的成员。但这仅测试分支数理性质，不是 WH3 物理模拟。并且 `0x0327E534` 的另一条件入口同时会查看 `group+0xD0C4`，所以也不能推断“CA 所有机制都只看平均距离”。

**最重要的因果限制：** 原始 V3 的被观测兵牌的 `0x030D5490` 旧 Hook 为零命中；这套群组度量是否直接负责 V3 的队列阶段切换，**仍没有动态执行证明**。不能把它现在改成“所有士兵必须到齐”的硬屏障。

## 4. 已排除的错误补丁

1. 不可把 `0x03914618` 新状态子动作的创建视为所有士兵主运动目标在同一帧完成切换。
2. 不可全局把 `member+0x7F8/+0x818` 清零或把 `member+0x710` 强设成统一阶段。
3. 不可修改 `0x030D572C` 的平均距离阈值来“证明解决”Shift，因为此路径未证实在 V3 实际触发，且其它原生 gate 可能共同作用。
4. RMB 与 Shift 共用这些原生成员函数；直接在它们的公共入口修改会同时影响普通 RMB。
5. 既有的“跳过 MOVE→MOVE 共享状态继承”实验 DLL仍保持**默认关闭**，不能当作本轮修复成果。
