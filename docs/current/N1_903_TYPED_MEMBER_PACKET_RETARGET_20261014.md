# BSC N1 — 9.0.3 原生 MOVE 成员目标包的朝向与位置二次修正（2026-10-14）

## 范围及验证

本轮在用户提供的固定 SHA256 `518c4f292f275142df13b96b9db704a3db7b4870b2c519df83d850596ecc822a` 的原始 Windows x64 EXE 上实际执行只读审计：**84/84 opcode 和 GNU objdump 指令起点、11/11 E8 直接调用、3/3 真实成员虚表槽、1/1 RIP-relative 构造器虚表、3/3 原始 float32 常量 PASS；10/10 本地回归 PASS**。这里的证明等级是 EXACT_EXE_STATIC，不是 Shift 实机命中，且没有 Native 游戏补丁。

## 关键实证：record[i] 只是初始几何，原生会按成员再改写

原始 `0x030D5490` 仍按相同下标绑定 `group_member[i]` 和 0x30 字节的 `record[i]`。阵型策略在 `record+0x22` 写 16 位朝向码；`0x030D54F7` 读取它并调用 `0x02F5F868` 构造成员 packet。该构造器最初于 `0x02F5F8AD` 写 `packet+0x40`，设置 `packet+0x50=0x26`，但发送点 `0x030D54EB` 还强制传入第五参数布尔 `1`，令构造器随后 E8 调用 `0x02F72520`。

`0x02F72520` 先设置 `packet+0x51` 的 0x02 位，并在 0x26 packet 的位检查满足后调用 `0x0307F478`。随后 `0x02F7254A` **覆盖写回同一个 `packet+0x40` 16 位字段**。所以旧文档把 `record[i]+0x22 → packet+0x40 → member+0xB0` 描述为简单直通只对最初复制阶段正确；成员实际收到的是可以经过二次修正的朝向参数。

### 修正条件与类型化成员身份

`0x0307F478` 先检查 `member+0x2E8` 来源对象。为空时直接保留原朝向；非空则读取成员 `member+0x984`，并检查关联对象 `+0x36CC`。当该状态为零时，浮点校正量（取整前）为 `(member+0x984 - 0.5) × 0x4000`，经原生 `0x00531E54` 转整数，加到原朝向 16 位结果，写回输出。状态非零时用零校正量；**不应凭浮点表达式假定所有模型都会取这一分支**。

同类真实成员构造器 `0x0304DAF8` 在 `0x0304DC70/0x0304DC84` 安装虚表 `0x0390D4F8`；该表 `+0x368=0x0306B9F0`、`+0x580=0x0306A990`、`+0x5B8=0x0306A8C0`。构造器在 `0x0304DDE6` 设置 `member+0x2E8` 来源，在 `0x0304E20E` 设置 `member+0x984`。后一个标量可以来自 context+0x90C 缓存，或由原生伪随机计算；静态常量为 0.15 和 1.2970169336767867e-05。此已识别生成区间约为 0.15..1.0，因此上述分支**取整前**可呈现 -31.5°..+45° 的角度偏移，这不是对玩家 Shift 折返的实机角速度测量。

### 位置字段也经过原生二次处理

`0x0306B9F0` 对 packet 标签 `0x26` 的 `0x20` 位走直接分支，且 `0x02F72520` 设置的 `packet+0x51` 位 0x02，会使接收器在对应条件下调用 `0x0307F5C8`。经 `0x0307F690 → 0x0307F4E4` 计算成员局部位置偏移，`0x0307F5C8` 还会沿原生群组/路线上下文进入 `0x03107FD8` 的空间路线处理。因此阵型 `record[i]` 的初始坐标不是该路径最终的 motor goal。

本专用 packet ctor 从 `record` 的 R8 来源直接取的偏移是 +0,+4,+8,+0x10,+0x18，未直接搬运 `record+0x20` 或 `+0x2C` 标志位；不代表它们在阵型生成器或其他任务系统中完全无作用。

## 对跨路段 Shift 修复的收敛意义

**禁止**直接把 `record[i]`、`packet+0x40` 或 `member+0x984` 全局清零或调成同一方向；这可能同时破坏普通 RMB、CA 渐进转弯和成员避障。只有当能在同一 queued MOVE state=1 实例中证明成员目标对应出错，而且证明安全补丁位置位于这些原生个体修正的正确前后阶段，才可制作最小版本守卫补丁。当前缺的是从后继 `task+0x160` 到具体 group/record[i] 的对象身份，以及最终 member motor goal 与那一实例的交叉验证。
