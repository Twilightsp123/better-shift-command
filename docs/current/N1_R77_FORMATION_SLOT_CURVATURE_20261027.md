# BSC R77 — 当前 EXE 阵型固定索引分配与群体挤压运动学正反例（2026-10-27）

**目标纠正：同兵牌成员挤压是群体空间运动现象，不是 CA 的某个动作代码。** 本轮从实际阵型槽位产生与成员索引配对重审；不再无限寻找“挤压动作”或把单兵状态位直接视作根因。

## 输入与验证等级
当前私有 Windows x64 Warhammer3.exe SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`，232531920 字节，ImageBase `0x140000000`。**原始文件静态核验**：66/66 整条 opcode + GNU objdump 真实指令起点、9/9 E8、3/3 PE unwind 函数范围、1/1 具体普通成员虚表+0x368；32/32 本地 Python 测试（含两项实际原始 EXE 检验）。GitHub CI 无 EXE 时会明确跳过这两项。未运行 WH3/安装 Hook/形成 gameplay 修复。

## 本轮真正新增的现版数据关系
旧文件的 `0x030D5490` **不是**当前版本有效地址。新版 `0x0327ECA4` 的受门槛控制 A 分支 `0x0327ED17 → 0x030DA5D8`，该函数先 `0x030DA681 → 0x03102B28` 路线转换，再 `0x030DA68F → 0x030DA51C` 条件分发；B 分支另走 `0x0327ED3C → 0x03268920`，两条不能当成每个 queued Shift 都必然走 A。

**同一 `0x030DA51C` Group-A fanout 函数：**
- `0x030DA52E` 从 `Group+0xB30` 获取实际多态阵型策略，`0x030DA556` 调策略 vtable+0x48 生成目标记录向量。
- `0x030DA561/565/569/572` 使用 Group 成员列表与 `i*0x30`（48 字节）定位第 i 个目标记录；`0x030DA57C` 从 `Group+0x28` 获得 `member[i]`。
- `0x030DA583` 取 `record[i]+0x22` 初始朝向种子，`0x030DA588` 构建成员数据，`0x030DA59B` 通过该成员 virtual+0x368 发包。循环随后 `i++` 并检查当前 Group 成员数；离开循环调用 Group virtual+0x20 后处理。
- **因此此段原生循环按相同索引 `member[i] → record[i]` 配对，没有在这个循环里按实时坐标重做全局最短距离分配。** 但策略产生目标的前置布局、下游 packet 的朝向补偿和最终 reference-aware 世界目标不同。**record[i] 不是已证的最终 motor goal。**

## 对“固定索引必挤压”的定量反例
离线 3×3、初始最近间距为 3 个**数学单位**，转向目标为整体180°：

| 理想化路径 | 最小同时间距（数学单位） | 含义 |
|---|---:|---|
| 固定槽位+180°直线插值 | ~0（中点九人重合） | 特定直线模型灾难性压缩，**不是 CA 已证实际算法** |
| 一次90°直线插值 | 2.1213 | 小于3，但不能仅凭这一点断言物理碰撞 |
| 两次90°直线插值 | 2.1213 | 不能把单次直线180°全重合反例直接套给 CA 渐进弯道 |
| 同固定索引+连续刚性180°旋转 | 3.0000 | **有固定索引但完全不压缩**，直接否定固定索引必然有错 |
| 相同终点但成员相位人为滞后/超前±0.18 | 1.4687 | 合成例说明仅成员阶段不同也会挤近，非 CA 参数 |

独立曲率宽度模型：理想中心线曲率半径 R 与横向阵型半宽 H，内外侧成员局部切向前进系数为 `1-H/R`、`1+H/R`。若 R≤H，维持严格刚性且所有成员持续向前可能不可兼得；但这**不意味着物理重合必发生**，可能改半径、局部逆向或允许队形变形。R=2,H=3 得 -0.5/2.5；R=12,H=3 得 .75/1.25。皆为运动学说明，不是 WH3 常量或游戏实际转弯半径。

**不能直接以 Hungarian/最近距离换位当修复：** 对中心不平移的对称3×3阵型，180°目标集合等于初始位置集合；单纯最小位移分配甚至可以让全队不动，却破坏真实朝向、槽位身份、相邻关系和战斗语义。

## 未闭合的根因与 R78 边界
1. 玩家普通 Shift 180°折返究竟命中 A/B 哪条原生路径及何种具体策略（旧 mode3 例不能自动宣称为新版默认）。
2. `record[i]` 如何经过成员接收 `+0x368`、原生二次角度/位置补偿与参考框架解析变成同一成员的最终 world goal。
3. 真正的兵模中心轨迹与转向相位、内外侧转向速度/避障，能否在相同时间对应到新旧目标。过去用户已确认缺陷存在；**不再让用户重复证明**，但现有历史汇总不能反算每名士兵真实路径。
