# BSC 本对话第29轮 / R63 — 原生侧向候选容器到路线对象的边界（2026-10-23）

**唯一目的：** 在保留 CA 原生 Shift MOVE 队列、渐进转弯、避障、普通 RMB 和 Shift ATTACK 的前提下，研究平滑折返的真实因果链。**没有发布 Native gameplay Patch。**

## 实际核验

用户提供的新版 Win64 `Warhammer3.exe` 完整 SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`，大小232531920字节；ImageBase `0x140000000`，地址均 RVA。本轮对真实 EXE 只读验证 **90/90 机器码与 objdump 指令起点、13/13 直接 E8、6/6 跳转、31/31 类型化操作数、6 个 PE unwind 函数和 1 个无 unwind 叶函数**。独立本地 **21/21 unittest PASS（包含真实 EXE）**，无私有 EXE 时 **20 PASS / 1 SKIP**。又从 ZIP 独立解压，真实 EXE **21/21 PASS**。不把合成门槛反例当实机数据。

## R62 之后真正新增的三段原生证据

1. **同一候选容器：** R62 已证明 `0x03114BF4` 使用记录 `+0x44` 的派生侧角，在候选工作对象 `+0x1A8/+0x1AC` 中计算空间点。本轮确认 `0x0312AAC4` 的 `0x0312AB99 CALL 0x03114BF4` 存在 AL=1 才能进入相关主分支的 `0x0312ABA5` 门槛。其局部 `[RBP+0x1E0]` 经 `0x0312B060 CALL 0x030C72F0` 产生候选记录，再由 `0x0312B6C4 / 0x0312B6CE` 调用 `0x030EE9BC` 追加到 R14 所指容器。工作对象与待追加记录**类型不同，不能声称直接逐字节复制了侧向点**。
2. **真正证明两端容器身份一致：** 转换器 `0x03102E14 LEA RAX,[0x04367228]`，于 `0x03102E27` 将其保存为 Win64 第六实参；生成器以 `RBP=entryRSP−0x4D8`，在 `0x0312AAEF MOV R14,[RBP+0x508]` 读回同一第六实参。因此 R14 与转换器容器完全一致。容器 `+0x00` 容量、`+0x04` 记录数、`+0x08` 数组指针；每条 `0xD0` 字节，`0x030EE9BC` 经 `0x030C71E0` 拷贝字段直到记录 `+0xCC` 并增加 count。
3. **进入路线对象分配的条件：** `0x03102E38` 调生成器；`0x03102E40/42` 的返回0进入后备路径；`0x03102E48/4E` 对容器计数为0时跳过候选构造。有候选时，按 `index×0xD0+[0x04367230]` 访问记录；`0x03102EAE/EB7` 把候选字段传给 `0x03121498` 转换；`0x03102EF8/F08` 用变换后的结果执行 `0x030C7058` 生成路线对象，`0x03102F1A` 再交给 `0x030CC8E4`。叶函数 `0x030C7058..0x030C70EE` 已独立解码和边界验证；在路线对象 `+0x18` 保存变换后的数据。转换器某些返回分支使用 `0x03103144 RAX=RBX`，调用者 `0x03126B46` 可保存至 `node+0x70`。

## 不得越界解释

- **已证：** 侧向角被真实几何处理消费，候选生成流程具有向同一个转换器容器追加 `0xD0` 字节记录的路径；候选非空且其他条件满足时，转换器尝试基于这些记录构造路线对象。
- **尚未证实：** `work+0x1A8` 中那一个由 ±90° 派生的点，是否确切对应最终保留的某条 `0xD0` 记录；这条记录是否被求解器选中、是否成为 B2 的实际 packet 目标，或是否与某次玩家 Shift 折返挤压有关。中间存在几何 helper、虚调用、分支选择和可能的 NULL 返回。
- **禁止：** 直接修改 `0x4000` 侧角、全局锁转向侧、清理 B2 缓存或用 Lua 重发 MOVE。当前 `root_cause_proven=false`、`actual_shift_side_flip_observed=false`、`native_gameplay_patch_authorized=false`。
