# BSC R84 — 当前 EXE 的成员局部候选引用与对象状态处理（2026-10-27）

**结论：已证明有类型的候选引用读者，尚未发现有类型的运行期指针写者；群体转向挤压根因仍未闭合。** 用户确认的故障是同一兵牌内多名士兵在原生 Shift 连续 MOVE 折返时轨迹相互干扰的空间现象，并不是需要找到的某个游戏“挤压动作”。

## 真实成员类型与字段消费者

1. 普通成员构造虚表 `0x03912950 + 0x4A0` 实际安装 `0x030751E4`。该函数在 `0x030751EA` 将本次 RCX 成员保存到 RBX。`0x03075202` 从**同一个成员**加载 QWORD `member+0x738`，`0x0307520C` 以 NULL 门槛判断；非空时 `0x0307520E E8→0x03126964`。
2. `0x03126964` 的 RCX 是被引用对象，非 member 本体。它沿 `object+0x08→context+0x440` 检查状态，也读取自身 `+0xD0/+0xD1`，条件性遍历 `+0xC0` 关联项并可能递减关联对象 `+0xBC`。最后可在 `0x031269BF` 将该对象的 `+0xD1` 置 1。**这是真正的关联对象状态处理，不是写回 member+0x738 或直接移动士兵。**
3. R80 已证明 `0x0311F34C` 收到 `RCX=&member+0x718` 内嵌子控制器。该函数从 `controller+0x20`（即 `member+0x738`）读候选选择对象，再由其 `+0xA0` 提供 `0x03132178` 的一项选择参数。本轮对 `0x0311F34C..0x0312096B` **完整函数体**的指令逐条审计，发现 `controller+0x20` **7 处直接读取、0 处直接写入**。不排除间接调用修改、别名写入或其它函数写入。
4. 本地成员工作函数 `0x03076F64` 在 `0x030770CD`、`0x03077147` 依成员状态分支读取 `member+0x738`。普通成员构造器 `0x03052F82` 把该字段初始化为 NULL；它不表示运行期永远是 NULL。

## 被明确排除的同偏移伪写者

- `0x0300BB6A`：`MOV DWORD [RDI+0x738],EAX`，属于 `0x0300B178` 函数内的**另一辅助对象**，RDI 并非由普通 member 的 RCX 传入。
- `0x0303A16A`：`MOV DWORD [RSI+0x738],EAX`，属于另一记录更新函数。这两条是 **32 位写入**，不是有类型的普通士兵 `+0x738` **64 位引用赋值**。不能因为十六进制偏移恰好一样就把它们归于成员导航目标系统。

## 核验及负结论范围

用户原始 EXE 的完整本地离线校验为 **55/55 个真实原始指令起点与原字节、4/4 直接 E8、7/7 PE 函数范围和普通成员 vtable +0x4A0**；**25/25 Python unittest PASS**（其中两项确实加载原始 EXE，另含 llvm-objdump 的完全解码起点确认）。公开 GitHub 提供全部 55 pin、4 条 E8、7 函数、虚表静态核验以及 synthetic negative tests；由于 CI 无商业 EXE，相应实际 EXE 测试会跳过。完整离线 ZIP 保存反汇编、真实原码校验日志、R83 历史 ZIP；绝不分发游戏 EXE。

**不允许升级的结论：**目前**没有**定位到该字段的真实**运行期引用写者**，更没有证明它保存 Shift 路点序号、成员目标选择异常、同一 queued MOVE 任务代际不一致或挤压的物理根因。不能用合成轨迹或简单相同指针据此修改成员控制器。
