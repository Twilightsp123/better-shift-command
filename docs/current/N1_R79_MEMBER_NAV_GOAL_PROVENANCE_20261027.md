# BSC R79 — 当前 EXE 成员持久导航目标的来源和提交控制流（2026-10-27）

**这是对同兵牌群体轨迹挤压的逆向研究，不是查找某个“挤压动作”或已完成补丁。** 精确用户提供 Windows x64 Warhammer3.exe SHA256 `9bd58c63bd7fc5c9909b3d3d9b6b7a6ae4eac784369bf91a9e53c3e9f42be496`，232531920 bytes，ImageBase `0x140000000`。以下皆为 RVA。完全静态只读，未加载游戏或安装 Hook。

## R79 的实际正证据：同成员目标从暂存记录进入持久记录

1. `0x03072EB8` 在 `0x03072EBE` 保存 `RCX=member` 到 RBX。若 `member+0xB20==NULL`，`0x03072F17/1A` 以该 **同一 RBX** 调用 `0x03076F64`。另外 `0x03076E48` 的 `0x03076ECA` 也从当前同一成员调用 `0x03076F64`；两个调用的前置条件不能合并。
2. `0x03076F64` 先有可条件性使用**旧暂存**数据的调用：`0x0307710E` 读取 `member+0x850`，`0x03077115` 取 `&member+0x838`，`0x03077127` 调真实 setter `0x0311E5DC`。
3. 同一函数的另一受条件保护路径，在 `0x0307722B` 调 `0x0311F34C` 生成目标记录：上下文含成员+0x910、组/参考/状态多项输入，来源**尚未被证明就是 original queued Shift 路段**。其返回记录在 `0x03077240/43` 拷贝16B至 `member+0x838`，`0x03077246/4B` 拷贝8B参考至暂存+0x10；`0x030772EA` 等组合标志至 `member+0x850`；满足额外条件才在 `0x03077409..1D` 以同一成员 + 这份暂存目标调用 `0x0311E5DC`。
4. **次序纠错：**不能因为两个调用都在 `0x03076F64` 内，就说每次先生成新目标然后提交两次。`0x03077127` 比后续生成器早；两条分支是否在一次具体 Shift 调用同时执行，并没有运行时证据。

## setter 不是无条件的路点更新器

`0x0311E5DC(RCX=member,RDX=goal_record,XMM2=scalar,R9D=flags)` 的门槛：

- 若 `member+0x228==1`，入口直接退出，**本次不执行正常持久目标拷贝**。
- 若 `member+0x30!=NULL` 且 `R9D bit15` 为真，转至 `0x0312C00C` 特殊处理并跳过正常复制；由某个调用者传入 `0x8003` 不能自动推断普通写入必发生。
- 其它常规路径中，`R9D bit9` 为0，且新旧目标引用 `source+0x10`、朝向 `source+0x0C` 相同、XYZ 每一分量绝对变化 **不超过原始浮点常量 `0.01f`** 时，可跳过对 `member+0x1B0/+0x24C` 的清零。否则这两字段会清零。
- **正常路径即使几何差很小，仍执行 `0x0311E6C7/CA` 把新记录前16B拷入 `member+0x1E0`，`0x0311E6D1/E8` 把源+0x10的8B引用拷入 `member+0x1F0`，再处理状态。** 绝不能把 0.01f 称为 Shift 路点到达阈值或“不更新目标”的阈值。
