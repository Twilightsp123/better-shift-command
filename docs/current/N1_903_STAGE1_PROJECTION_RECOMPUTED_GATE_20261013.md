# BSC N1 · 2026-10-13 · 后继 MOVE 继承旧方向的二重原生门槛

## 本轮结论（纠正此前将旧方向投影视为每段必执行的推断）

**只有命中某个原生成功门槛的后继 MOVE，才会把旧子任务引用从 `task+0x158` 转存到 `nextSubtask+0x20`，并沿旧位置、旧方向、旧长度投影。** 后继 MOVE 进入 state=1 本身不足以证明已经执行投影。前面研究的 `0x03040864` 只是“接受复用任务、改写几何、标记 state=1”；真正投影是否发生要看随后共同的任务构造器结果。

本轮独立在真实、精确 SHA256 `518c4f292f275142df13b96b9db704a3db7b4870b2c519df83d850596ecc822a` 的原始 EXE 上验证了 **36/36 处新增／关键机器码字节及实际反汇编指令起点、3/3 条直接调用边、3/3 条条件跳转目标**，并运行 **6/6 本地测试**。验证代码为只读脚本，未修改 EXE、未进行 Frida 插桩。研究分支维护的 `audit_inherited_move_projection.py` 已进一步合并先前 27 处 guard，总计 57 个原始 opcode 站点；公开 GitHub CI 可验证合同，但因不存原始 EXE，其 exact PE 测试应在带原始 EXE 的环境执行。两种验证等级要分清。

## 从旧任务复用到新路段的真实分叉

1. MOVE 槽位 `vtable+0x48` (`0x03040864`) 在通过先前 `vtable+0x40` 条件后把原来的大任务转移给后继槽位，令 `task+0x20=1`，更新 `+0x120/+0x130/+0x140`。它不是必然发生：旧任务需要状态 4、`+0x24`、`+0x158` 和群组 eligibility 等条件。
2. 大任务状态机 `0x0311DE74` 走 state=1 路径 `0x0311DEC0 -> 0x0311E578`。它在 `0x0311E5B3` 将**当前任务的 `+0x24` 重置为 0**，在 `0x0311E5C2..0x0311E61E` 更新当前段几何。
3. 在 `0x0311E636` 调用公共构造／生成函数 `0x0311E80C`；**新的 state=0 路径在 `0x0311E772` 也调用同一函数**。因此只看这个函数命中不能判断玩家按 RMB 或 Shift。
4. 公共生成器 `0x0311E80C` 自己会计算新 `task+0x24`：`0x0311EB10 mov [rsi+0x24],dil`。一个重要受限分支从 `0x0311EAC7 call 0x0310F560` 获取 AL，又在 `0x0311EAD8` 将当前调用上下文 `[rbx+0x4E4]` 与寄存器 ECX=2 比较。在**确实走到这条分支**时，只有 `AL != 0` 且 `[rbx+0x4E4] >= 2` 才会令 `DIL=1` 并写出 `task+0x24=1`；其它路径还可能提前退出，**这不是整个函数所有返回路径的普适公式**。目前不命名 `+0x4E4` 的真实结构字段含义。
5. 返回 state=1 后，`0x0311E63B cmp [task+0x24],1`；`0x0311E63F jne 0x0311E7E0`。**不等于 1 时，直接离开本轮 state=1 逻辑，不执行本轮旧方向投影，也不执行 `0x0311E6EC` 清理主指针。** 等于 1 才继续：
   - `0x0311E645` 读 `task+0x158`；
   - `0x0311E64C` 将旧子任务引用放入 `nextSubtask+0x20`；
   - `0x0311E65E..0x0311E6E7` 通过旧位置、方向分量、旧长度和系数 `0.5f` 投影一对局部目标；
   - `0x0311E6EC` 清理 **大任务** `+0x158`，但 `nextSubtask+0x20` 仍可持有对旧子任务的引用。

原生核心条件（**仅限已识别的这条 reached-branch**）：
```text
native helper AL != 0 AND caller context [RBX+0x4E4] >= 2
  => r8b!=0 and DL==0
  => DIL=1
  => [task+0x24]=1
  => stage1 projector transfers old subtask + computes symmetric projections
otherwise:
  [task+0x24] remains 0 in this branch
  => stage1 skips old projection and main +0x158 clear
```

**不应误认：** `[RBX+0x4E4]` 目前只是按原生代码确定的数字门槛，不知道是不是成员数量、路段数量、阵型段或其他计数。没有实机记录对应实例，不能因为它和“折返挤压”同时出现就直接调它；`0x0310F560` 内部复杂条件仍未完全语义定型。

## 与 RMB vs Shift 的真实差别

已经证明：统一 MOVE 的 `R9B→DL` 决定清队列／追加队列；MOVE 槽位在满足条件时可移交旧任务；**fresh state=0 和 inherited state=1 都调用相同原生生成器**，但只有后者再根据结果尝试旧方向投影。

尚未证明：普通 RMB 的任意 MOVE 绝不经过状态 1，玩家 Shift 折返的每个新路段都命中这个成功门槛，以及**成功投影本身**是否造成士兵相向移动。旧实机 JSONL 中没有对应的 `task`、`nextSubtask`、来源键位实例关联。因此目前不能根据本次静态结果制作补丁。

## 对未来补丁设计的直接约束

**不能**无条件清 `task+0x158`、删除 `nextSubtask+0x20`、强制 `task+0x24=0/1`、修改 `0x5` 单位判断或让士兵瞬转。这里的旧方向投影**本来就是有条件发生**的，且共用生成器还可能更改任务状态。修改这些字段可能让 CA 原生渐进转向失效、任务反复等待或者槽位失去合法引用。
